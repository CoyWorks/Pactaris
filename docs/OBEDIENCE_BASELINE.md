Sources:

- [Official FAQ](https://obedienceapp.com/faq): count targets, one-off scheduling, multiple partners, switches, timezone and category behavior.

- [Official homepage](https://obedienceapp.com/): testimonials and references to companion products; do not treat customer wishes as verified native functionality.

The FAQ explains multi-partner and switch support; the project extends this into explicit many-participant dynamic spaces with independent technical rights. Basic progress charts belong in the core. Automatic outcomes require explicit prior configuration, current consent and pause guards; disabling them is always possible and withdrawal never earns a consequence.

Embrace is a separate companion journal product. Do not claim its full journaling feature set is native Obedience parity. Basic notes (#66) are distinct from optional richer journaling (#46). Free/paid capacities must account for habits, catalog entries and basic communication while preserving the usable free dynamic.

Use this mapping in the pilot checklist (#34). Verify each core flow through the actual app; a present schema or a UI mockup is not completion.
